# 2.3 Token 与分词器

在大语言模型（LLM）的世界中，模型无法直接理解人类的文字。**Token（标记）** 和 **Tokenizer（分词器）** 构成了人类自然语言与计算机数字化特征向量（Embeddings）之间的“翻译官”。

---

## 一、 什么是 Token？

**Token 是大语言模型处理文本的基本语义单元。** 

* **核心实体：** Token 可以是一个完整的单词、一个词根、一个字符，甚至是一个标点符号。
* **数字映射：** 每个 Token 在分词器的词表（Vocabulary）中都对应一个唯一的**整数 ID**。模型内部的一切计算，都是基于这些 ID 转换后的向量完成的。

### 1. 不同的切分视角
以英文单词 `unhappiness` 为例：
* **按单词切分：** `["unhappiness"]` （词表会过于臃肿）
* **按字母切分：** `["u", "n", "h", "a", "p", "p", "i", "n", "e", "s", "s"]` （失去了字母组合的语义）
* **按子词（Subword）切分：** `["un", "happi", "ness"]` （目前大模型的主流选择，既控制词表大小，又保留前缀、词根语义）

### 2. 语言差异带来的“Token 成本”
由于分词器通常基于主流英文语料训练，不同语言的 Token 压缩率存在显著差异：
* **英文：** 1 个单词通常约等于 **1.3 个 Token**。
* **中文：** 1 个汉字通常等于 **1 ~ 2 个 Token**（部分偏门字甚至占用更多）。
* **代码：** 由于存在大量空格和缩进，Token 消耗极快。

---

## 二、 什么是分词器（Tokenizer）？

**Tokenizer 是负责将原始文本（Text）与 Token ID 序列进行双向转换的工具。**

### 1. 核心工作流
* **编码（Encode / Tokenization）：** 原始文本 → 切分为 Token → 映射为词表 ID。
* **解码（Decode）：** 模型生成的 Token ID 序列 → 映射回 Token →  拼接为可读文本。

### 2. 现代大模型的三大主流分词算法
现代大模型普遍采用**子词切分（Subword Tokenization）**算法，主要包括以下三种：

* **BPE (Byte-Pair Encoding，字节对编码)：**
  * **原理：** 从字符级别开始，不断将词料库中频率最高的“字符对”合并为新的 Token，直到达到预设词表大小。
  * **代表模型：** GPT 系列（如 GPT-4、GPT-4o）、LLaMA 系列。
* **WordPiece (词块分词)：**
  * **原理：** 与 BPE 类似，但合并选择不仅看频率，而是看合并后能否最大化训练语料的语言模型似然度（更倾向于合并语义关联强的组合）。
  * **代表模型：** BERT。
* **Unigram (一元语言模型)：**
  * **原理：** 反向操作。先构建一个极其巨大的基础词表，然后基于概率模型不断剔除对减小语言模型损失贡献最小的 Token。
  * **代表模型：** T5、SentencePiece 框架常选。

---

## 三、 特殊 Token（Special Tokens）

分词器的词表中除了常规词汇，还包含控制模型行为的特殊 Token，常见的有：
* `<|endoftext|>` 或 `</s>`：**结束标记**。告诉模型文本已结束，停止生成。
* `<s>` 或 `<|startoftext|>`：**开始标记**。提示模型接下来是文本输入。
* `<pad>`：**填充标记**。在多条文本批量训练时，将较短的文本对齐到相同长度。
* `<unk>`：**未知词标记**。当文本中出现词表完全未包含的古怪字符时使用。

## 四、 为什么 Tokenizer 对大模型至关重要？

分词器的优劣直接影响模型的算力成本和能力表现：

* **直接影响上下文窗口：** 同样一段文本，如果分词器效率低下（切得太碎），占用的 Token 数就多，会导致模型的有效上下文空间变相“缩水”。
* **影响多语言能力：** 早期 LLaMA 的词表只有 3.2 万，其中中文极少，导致中文被切得非常零散（一句话耗费大量 Token），随着 LLaMA 3 词表扩大到 12.8 万，其中文表达和推理效率大幅提升。
* **解决 OOV（Out-of-Vocabulary）问题：** 通过子词或字节（Byte）级切分，现代分词器几乎可以组合出任何未见过的生僻词，避免了传统 NLP 频繁遇到未知词（`<unk>`）的尴尬。


> 为什么要分词？一是压缩序列长度（更省计算），二是让模型学到"词/子词"层面的规律。中文模型通常对中文专门优化，一个字或词一个 token。
